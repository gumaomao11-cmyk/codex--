# 调仓执行规范（SOP）：分批 / 限价 / 避开局部高点

> 目标：杜绝"买在信号生成的当天，成交却在局部最高点"这类执行层亏损。
> 上次 08-17 就买在 AI/半导体短期顶部，4 天 -11.7%，主因是**一次性市价单追在波段顶部**，策略本身没坏。

## 一、铁律（每次调仓必须遵守）

1. **禁止一次性把所有资金用市价单买入。**
2. **调仓一律分批**：默认 3 批，每批 1/3，分散到连续 3 个交易日执行。
3. **一律用限价单**，限价 = 当时市价往下 1~3%（宁可不成交，也不追高）。
4. **收盘前或盘前生成计划**，开盘按计划分批挂单；当日不成交就撤单，次日重新挂，**不要改价追高**。
5. **离 60 日高点太近的标的，前批先等回踩**再挂单，绝不梭哈。

## 二、工具用法

### 1）生成本次调仓的"分批限价计划"
```powershell
cd F:\even-codex\lianghua2
python plan_rebalance.py --csv backtest_output\current_holdings_6m_skip1_top10.csv
```
会打印每只的：
- 现价 / 60 日高点 / 距高点比例
- `接近高点!等回踩` 的标记（≈追高风险）
- 每批的限价单价格

并保存计划到：`backtest_output\rebalance_plan_YYYYMMDD.csv`

### 2）关键参数（可按需调整）
| 参数 | 默认 | 含义 |
|---|---|---|
| `--tranches` | 3 | 分几批 |
| `--buffer`   | 0.02 | 限价低于市价的缓冲（2%） |
| `--high-win` | 60  | 判断局部高点的窗口（交易日） |
| `--chase-th` | 0.97 | 距高点 97% 以上判定为"追高危险" |
| `--budget`   | 20000 | 本期预算（会均分到每只） |

### 3）到 Alpaca 手动分批挂限价单
按计划 CSV，每天开盘挂 1 批限价 buy 单（target ticker 不在仓里的就买，已在仓的就按差异补足）。

> 说明：paper/实盘都建议手动分批执行，避免市价单追高。

## 三、买入/卖出规则

### 卖出（旧持仓调出）
- 可以一次性市价卖（卖出不追高无风险），但若担心滑点，也可分 2 批。
- 先卖后买，避免同时挂单把现金占满。

### 买入（新持仓调入）
- 逐日分批，限价单，宁可不成交。
- 接近 60 日高点的：**这批先空着，等回踩 2~3% 再买**；回踩不到就留到下月。

## 四、纪律清单（调仓当天逐条勾）
- [ ] 生成了 `rebalance_plan_*.csv`
- [ ] 每只分配金额 = 预算 / 只数（等权），没有金额分配错误
- [ ] 每只都是限价单，不是市价单
- [ ] 分 ≥2 批，最好 3 批
- [ ] 接近 60 日高点的标的已标记，已推迟/降速
- [ ] 先卖后买
- [ ] 未成交单已撤，不追价

## 五、为什么上次会买在顶部（复盘，避免复发）
- `current_holdings` 用 **signal_date（07-31）** 的价格算份额和限价
- 但实际成交走了 `alpaca_buy.py` 的 **market order**，等到 08-17 才买，价格已经冲到波段顶
- 结果：份额还是按 07-31 算的 $2,000，但成本价是 08-17 高点 → 一回调就全亏
- **修复**：以后用最新价生成计划 + 分批限价，不要再跨多天市价追高
## 六、主干 + 卫星（机会仓）分层

- **主干仓**：月频 top10，4 批 × 5 个交易日限价入场（见上），占预算 ~85%
- **卫星仓（机会仓）**：对近期爆发但未进 top10 的标的（如某医药股）做 ≤15% 试探仓

### 卫星仓用法
```powershell
python satellite_plan.py --tickers "MRNA" --budget 3000
```
- 输出 `satellite_plan_YYYYMMDD.csv` + 记录 `satellite_targets.json`
- paper_tracker 每日会把卫星仓**单独列一段**（不计入核心策略回测）
- 触发规则同主干：接近 60 日高点先等回踩，分 2 批限价买

### 仓位上限
- 主干 85% + 卫星 ≤15%，卫星总敞口不许超过预算 15%（默认 3000/20000）
- 卫星仓亏损**单独看**，不影响主干策略评估
